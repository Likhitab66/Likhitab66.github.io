The problem

An empty shelf costs a retailer twice: the lost sale, and a sales history that now understates demand. This is a rebuild of my MS capstone on synthetic data, 200 SKUs over 104 weeks. The simulator records true demand next to fulfilled sales, so every metric can be checked against ground truth.

How it works

  1. Simulate

    A seeded simulator covers 200 SKUs over 104 weeks across 6 categories, with seasonality, promotions, supplier lead times and a reorder-point policy. True demand and fulfilled sales are recorded separately, so stockouts are measurable.

  2. Measure

    WISP weights each SKU's in-stock status by its trailing sales velocity, shifted one week so a stockout can't shrink its own weight.

  3. Predict

    A random forest scores the risk of a stockout in the next 4 weeks, trained on a time-based split with an embargo.

  4. Forecast

    A global HistGradientBoosting model forecasts weekly sales per SKU, backtested over 3 expanding-window folds.

  5. Publish

    A self-contained Plotly dashboard, plus star-schema CSV exports and a DAX rebuild guide for Power BI.

How I measured it

  • WISP 92.2% vs plain in-stock 91.1% overall
  • Stockout-risk model: precision 0.693, recall 0.869, PR-AUC 0.849, against a test-set base rate of 33.1%
  • 88 of 200 SKUs flagged high-risk in the latest simulated week, a holiday-season dip when overall WISP fell to 84.9%
  • Forecast backtest WAPE 23.8%. MAPE (33.2%) overweights low-volume weeks, so I report WAPE as the headline.
  • In the simulator, 5.3% of total demand is lost to stockouts. That is a property of the synthetic data, not a model result.

Limits

  • Synthetic data from a seeded simulator, so the risk model partly learns the simulator's own rules. That is why supplier lead time tops the feature importances, and real data would be a harder test.
  • The Power BI piece is CSV exports and a written DAX rebuild guide, with no published report file.
  • The forecast has no naive baseline yet, so WAPE 23.8% has no reference point to beat.
  • WISP leads plain in-stock overall, but category by category the gap goes both ways: it falls below where fast sellers are the ones running out, as in Electronics.

What I'd tell the team

  • Start reorder-point reviews with the 88 of 200 SKUs flagged high-risk in the latest week, longest supplier lead times first.
  • On the test split the model's precision is 0.693 against a 33.1% base rate, so a flag is about twice as likely to be a real stockout as a random pick.
  • Report WISP next to plain in-stock, because the gap shows when the best sellers are the ones running out.
